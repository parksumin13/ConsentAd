# ConsentAd React Studio

광고주 / 권리자 / 플랫폼 전용 페이지와 공개 광고 목록을 제공하는 React 19 서비스입니다.
광고별 별도 Escrow 모델을 사용하며, 배포 시 광고마다 권리자·플랫폼 지급액, 등록 후 집행 기한, 활성화 후 사용 기간을 설정합니다. 기존 고정 조건 계약의 가져오기도 지원합니다.

## 시작하기 (Mac)

Node.js 22 이상을 설치한 뒤 프로젝트 폴더에서:

```sh
npm install
npm run build
npm run dev
```

터미널에 표시되는 localhost 주소를 MetaMask 확장이 설치된 Chrome에서 엽니다. 로컬 미디어와 목록은 Wrangler의 `.wrangler/state`에 저장합니다. 다른 기기에 공유하려면 서버를 배포해야 합니다. 공개 체인 기록은 로컬 서버 종료와 관계없이 남습니다.

## 실제 연결 순서

1. MetaMask: Bifrost Testnet, chain ID 49088. RPC https://public-01.testnet.bifrostnetwork.com/rpc
2. 광고주 / 권리자 / 플랫폼의 세 지갑에 수수료용 테스트 BFC를 준비합니다.
3. 상단 지갑 연결: 네트워크 전환과 지갑 소유 확인 메시지 서명을 진행합니다. 개인 키를 입력하지 않습니다.
4. 설정: 기존 CADToken 주소를 입력하고 확인합니다. 없으면 새 CADToken을 배포합니다.
5. 기존 계약 연결: 광고주 지갑에서 실제 배포된 ConsentAdEscrow 주소를 입력합니다. CADToken 주소나 지갑 주소를 넣지 않습니다.
6. 새 광고: 최종 MP4 (50MB 이하), 권리자와 플랫폼 지갑을 입력합니다. 웹에서 새 계약을 배포하고 실제 파일 SHA-256을 registerAd에 기록합니다. 배포와 등록은 각각 MetaMask 거래입니다.
7. 광고주 상세: CAD 지출 허용 → 해당 계약의 TOTAL_FEE만큼 예치.
8. 권리자 지갑으로 전환 → 재서명 → 권리자 페이지 → 원본 검토 (파일 해시 검증) → 승인 또는 거절.
9. 플랫폼 지갑으로 전환 → 재서명 → 플랫폼 페이지 → 원본 확인 또는 게시할 MP4 파일 대조 → 집행·정산.
10. 공개 목록에서 활성화된 광고를 재생합니다. 계약에 설정한 RIGHTS_FEE와 PLATFORM_FEE가 한 거래에서 지급됩니다. 종료 후 공개 신규 재생을 차단합니다.
11. 권리자가 거절하거나 기한이 지난 funded/approved 계약에서는 광고주가 환불할 수 있습니다.

기존 Remix VM 주소는 Bifrost에서 동작하지 않습니다. Bifrost에 배포한 실제 계약 주소를 사용합니다. 0x111... 같은 가상 영상 해시로 등록한 계약은 실제 MP4가 그 해시와 일치하지 않으므로 영상 연결을 위해 새 광고를 만드세요. 예시 모드의 광고·잔액은 모두 샘플이며 실제 거래할 수 없습니다.

## 여러 광고

기존 컨트랙트는 광고 하나당 Escrow 하나입니다. 새 광고마다 같은 Bifrost 체인에 새 계약을 배포하며, 사이트 공용 R2 목록에 광고별 계약 주소와 공개 메타데이터를 저장합니다. 이미 배포한 계약도 광고주가 등록할 수 있습니다. 원본에는 Factory나 전체 광고 열거 기능이 없으므로 사이트에 연결하지 않은 임의의 외부 계약을 자동 수집하지 않습니다. 지갑마다 목록을 필터링할 수 있지만 체인 정보는 공개입니다.

## 광고별 조건 설정 (업데이트)

새 광고 등록 폼에서 권리자/플랫폼 지급액을 정수 CAD로 입력하고, 집행 기한과 사용 기간을 각각 일·시간·분·초 단위로 지정합니다. 총 예치금은 지급액 합계입니다. 총액과 두 기간은 0보다 커야 합니다. 한 수령자의 지급액만 0으로 지정하는 것은 지원합니다.

계약은 constructor에서 위 조건을 immutable로 저장합니다. 배포된 계약 조건을 나중에 변경하는 함수는 없습니다. 다른 조건은 새 광고 계약으로 구분하며, 권리자 승인도 다시 받습니다. 기존 3개 생성자 입력 버전은 그대로 조회·거래 가능하지만 그 계약의 200/800·7일·30일을 변경할 수는 없습니다. 기존 CADToken은 재사용 가능합니다.

Remix의 새 ConsentAdEscrow 생성자 순서:
1. tokenAddress
2. rightsHolderAddress
3. platformAddress
4. rightsFee
5. platformFee
6. executionWindowSeconds
7. usagePeriodSeconds

예: 권리자 300 CAD / 플랫폼 700 CAD / 등록 후 14일 내 집행 / 집행 후 60일 사용은 `300, 700, 1209600, 5184000`을 마지막 네 입력에 넣습니다. 총액은 1,000 CAD입니다. Remix 숫자 입력은 초 단위이며 웹에서는 자동 변환합니다.

전체 Solidity 원본은 사이트의 `/ConsentAdStarter.sol`에서 확인할 수 있습니다. OpenZeppelin 5.4.0을 명시해 Remix와 웹 컴파일의 의존성을 맞춥니다.

## 보안과 접근

- 지갑 서명은 Origin, chain ID, 주소, nonce, 만료 시각을 포함합니다. nonce는 R2 ETag 조건부 쓰기로 한 번만 소비합니다.
- 서버 발급 HttpOnly 세션으로 참여자 지갑을 확인합니다. 계정 변경 시 세션을 종료합니다.
- 광고 등록·업로드는 체인의 advertiser와 일치하는 지갑만 가능합니다.
- 원본은 R2 비공개 키에 저장하고 공개 정적 경로에 포함하지 않습니다. API가 매번 체인 역할과 isPublishable을 검사합니다.
- 공개 썸네일은 캔버스에서 블러를 적용한 JPEG를 따로 생성합니다. 원본에 CSS 블러만 씌우는 방식이 아닙니다.
- 업로드와 원본 전달 시 실제 파일 SHA-256을 온체인 videoHash와 대조합니다. 불일치하면 기존 원본을 바꾸지 않습니다.
- 거래 실행 권한과 중복 정산, 기한 조건은 원본 컨트랙트가 최종 강제합니다.
- 권리자 지갑 지정은 실제 신원/초상권 소유 검증을 대신하지 않습니다. 오라클은 포함하지 않습니다.
- 이미 적법하게 열람하거나 다운로드한 영상의 복사·외부 재게시를 기술적으로 회수할 수는 없습니다. 외부 플랫폼의 독립 게시까지 차단하지 않습니다.
- 이 서비스는 표준 EOA MetaMask 서명을 지원합니다. 스마트 계약 지갑(EIP-1271)은 별도 확장 대상입니다.
- 거래 이벤트 조회는 노드 부하를 줄이기 위해 최근 200,000블록으로 제한하며, 현재 상태·잔액은 최신 체인 조회입니다.
- 호스팅 접근 권한과 지갑별 역할 권한은 별개입니다. 현재 호스팅은 기본 비공개이며 외부 팀원에게 열려면 Sites 공유 설정을 변경해야 합니다.

## 개발 구조

- src/main.jsx: React 역할별 페이지, 카드 목록, 등록·검토·거래 화면
- src/chain.js: 원본 ABI, Bifrost 설정, 역할·상태 조건
- src/style.css: 반응형 UI
- server/index.js: 지갑 인증, R2 공용 목록, 미디어 접근 제어, RPC 조회
- contracts/ConsentAdStarter.sol: 원본 승인·정산 로직 + 광고별 배포 조건 설정
- scripts/build.mjs: solc 원본 컴파일(Paris EVM), React 번들, Worker 패키징
- tests/protection.test.mjs: nonce 재사용, 권한, 변조, 만료 등 서버 테스트
- tests/contract.test.mjs: 배포 바이트코드로 맞춤 정산·기간·환불·중복 지급 차단을 검증하는 메모리 EVM 테스트
- src/terms.js: 금액·기간 입력 검증과 초 단위 변환

`npm test`로 검증합니다. 실제 Bifrost 거래 검증에는 테스트 BFC와 실제 배포 계약 주소가 필요합니다. 가스비 지불과 체인 배포는 지갑에서 직접 확인합니다.
